# 论文改进路线图（TODO）

> 目标：把当前工程作品（跌倒**检测**系统）升级为一篇可投稿 **CCF-C** 的研究论文。
> 核心策略：**把问题从「跌倒检测」重构为「跌倒提前预警（pre-impact anticipation）」**，
> 并把现有最独特的资产（4 阶段时间点标注 + 失衡中间态 + 居家场景）转化为贡献。
>
> 状态标记：`[ ]` 未开始 · `[~]` 进行中 · `[x]` 已完成
> 每条任务尽量标注**涉及文件**与**验收标准**，避免"改完不知道对不对"。

---

## 0. 现状结论

| 维度 | 现状 | 能否支撑 CCF-C |
|------|------|----------------|
| 工程完整度 | 数据→训练→推理→服务→前端全链路打通 | ✅ 超出平均 |
| 方法新颖性 | RTMDet + RTMPose + ST-GCN（均为 2018-2023 现成组件） | ❌ 无贡献点 |
| 评估严谨性 | 单种子 / 自定义混合切分 / 无 baseline 对比 | ❌ **阻断性** |
| 数据规模 | 279 段视频 | 🟠 偏小 |
| 差异化资产 | 4 阶段时间标注、失衡中间态、真实居家场景、完整部署 | ✅ **尚未利用** |

**一句话**：差的不是工作量，而是**"研究问题的形状"**。目前审稿人会判定为 *"a straightforward application of existing components"*。

## 1. Phase 0 · 阻断性问题（不修完，后面全部白做）

### 1.1 消灭受试者泄漏（Subject Leakage）🔴 最高优先级

- [ ] **排查**：确认当前切分是否把同一受试者的视频分到了训练集与验证集两侧
  - 涉及：`src/train.py:152-156`、`src/eval_model.py:51-54`、`src/search.py:55-59`
  - 现状：三处都用 `rng.shuffle(vid_idx)` 做**按视频**随机 8:2
  - 问题：CAUCAFall 的 `1_forward_falls.mp4` 与 `1_standing_falls.mp4` 属同一受试者，
    URFD 每位受试者也同时有跌倒与日常序列 → **同一人跨两侧**
- [ ] **实现** `src/split.py`：统一的划分模块，支持三种协议
  - `loso`：留一受试者（Leave-One-Subject-Out），论文主协议
  - `dataset`：跨数据集（train on A, test on B）
  - `video_random`：仅用于与旧结果对照，**不进论文**
- [ ] **改造**：`train.py` / `eval_model.py` / `search.py` 全部改为调用 `src/split.py`，
  消除三处重复的切分代码（同时消除"改一处忘一处"的风险）
- [ ] **验收**：打印切分后 `subject_id` 交集，必须为空集；重复运行结果一致

### 1.2 建立数据清单（Manifest）

- [ ] **实现** `src/make_manifest.py`，生成 `data/video_manifest.csv`
  - 列：`video_id, dataset, file_name, subject_id, is_fall, scenario, camera_view, fps, quality, notes`
  - 格式直接复用 [`../annotations/标注说明.txt`](../annotations/标注说明.txt) 里已设计的方案
  - `subject_id` 从文件名反推：URFD 按 `fall-XX` 序号规则，CAUCAFall 取 `subject-N` 前缀，clips 取 `c/h/L/o` 前缀
- [ ] **生成** `data/fall_events.csv`
  - 列：`video_id, risk_start_frame, fall_start_frame, impact_frame, stable_fallen_frame, quality, notes`
  - 可从 `annotations/*.xlsx` 与 `*_info.json` 自动汇总
- [ ] **验收**：279 段视频全部有 `subject_id`；`fall_events.csv` 覆盖所有跌倒段；两份 CSV 通过 `video_id` 可 join

### 1.3 修正窗口样本的相关性表述

- [ ] **修改** `src/dataset.py:63-65` 的评估口径
  - 现状：`window=30, stride=4` → 相邻窗口共享 26/30 帧
  - 问题："4054 个验证窗口"**不是 4054 个独立样本**，报告的置信区间被人为收窄一个数量级
- [ ] **方案**（二选一，论文中明确声明）
  - 方案 A：评估时使用 **`stride = window`（不重叠）**，牺牲样本量换取独立性
  - 方案 B：仍用 `stride=4`，但置信区间改用 **video-level bootstrap**（重采样整段视频，而非重采样窗口）
- [ ] **验收**：论文中汇报的 CI 是 video-level resample 得到的

### 1.4 文档与代码不一致（顺手修）

- [ ] `src/state_machine.py:32-36` 的默认参数是 `low=0.60/10次`、`mid=0.75/10次`、`high=0.90/10次`、`imm=0.90/10次`
  而 `docs/开发日志.md` 记录的是 `LOW 连续3次 / HIGH 连续2次 / IMMEDIATE 连续5次`
  → 统一为同一套数值，并在 `checkpoints/README.md` 中写明当前生效值
- [ ] `src/state_machine.py` 注释里出现 `MID_RISK`，而 `AlertLevel` 中还有 `HIGH_RISK`
  → 明确预警等级到底有几级（文档、代码、前端三处对齐）

**Phase 0 验收标准**：跑通 LOSO，拿到**真实的**性能数字。这个数字决定后续走哪条路（见第 9 节决策点）。

## 2. Phase 1 · 评估规范化

### 2.1 新增 `src/metrics.py`

- [ ] 阈值无关指标：**AUC-ROC**、**PR-AUC**、**EER**
- [ ] 固定工作点指标：`Precision@Recall=0.95`、`Recall@FPR=0.01`
- [ ] 部署指标：**FAR（false alarms per hour）**、报警次数/小时
- [ ] 预警专属指标：**Lead Time**（从首次触发 HIGH/IMMEDIATE 到 `impact_frame` 的帧数/秒数）
- [ ] 保留原有 P/R/F1、macro-F1、混淆矩阵
- [ ] **弃用** `score = avgF12 - 0.5*fp_rate`（自定义、不可比）；仅内部选超参时保留

- [ ] **验收**：`metrics.py` 对同一份预测输出能给出上述全部指标；数值与 `sklearn` 对齐（AUC 做单元对照）

### 2.2 统计严谨性

- [ ] **5 个随机种子**（`0,1,2,3,4`）重跑，汇报 **mean ± std**
- [ ] **冻结超参**：绝对不允许在验证集上调阈值/结构；`search.py` 的搜索结果需在独立划分上确认
- [ ] **显著性检验**：与最强 baseline 做配对检验（video-level bootstrap 或 McNemar）
- [ ] **验收**：论文所有主表都带 ± 与显著性标记

### 2.3 复现 baseline（≥5 个）

- [ ] 轻量对照：`LSTM`、`BiLSTM`、`Transformer`（骨架输入，自己实现）
- [ ] 已有路线：`TCN`（`src/tcn_model.py`）、`ST-GCN`（`src/stgcn_model.py`）
- [ ] 骨架 SOTA 迁移：`2s-AGCN`、`CTR-GCN`、`HD-GCN`、`PoseC3D`（mmpose 已内置 PoseC3D，成本最低）
- [ ] 同数据集已发表方法的**引用数值**（从原论文表格摘录并注明协议是否可对齐）
- [ ] **验收**：形成一张完整对比表，包含参数量、FLOPs、推理延迟

### 2.4 修掉"摔倒类 Precision 0.49"

- [ ] 诊断 FP 来源：是"失衡→摔倒"混淆，还是"正常→摔倒"混淆（用混淆矩阵拆开）
- [ ] 尝试：类别权重 / Focal Loss / 代价敏感损失 / 后处理校准
- [ ] 若无法显著提升，**改用工作点曲线说明**：汇报 `Recall=0.95` 时的 Precision 与 FAR，
      并在文中明确"以满足召回目标为前提比较精度"
- [ ] **验收**：论文中不再出现"无法解释的低 Precision"，或已给出 Pareto 曲线支撑

**Phase 1 验收标准**：得到一套**与文献可比**的 LOSO 结果表 + 5 个 baseline 对比。

## 3. Phase 2 · 方法创新（核心贡献）

> 四条路线选 **1~2 条**深入，不要都做浅。推荐 **B1 + B2 组合**。

### B1. 非对称时序软标签（替代现有启发式）⭐ 推荐

- [ ] **现状问题**：`src/dataset.py:65` 的 `window_labels[-label_tail:].max()` 是拍脑袋超参（`label_tail = window//3`）
- [ ] **升级 1**：把硬 max 换成**随阶段递增的软目标曲线**，与 4 阶段标注对齐
  （`risk_start → fall_start → impact → stable_fallen` 对应递增风险值）
- [ ] **升级 2**：引入**类别代价矩阵**（漏检代价 ≫ 误报代价），把"宁可误报不可漏报"写进损失函数
- [ ] **消融**：`label_tail` 取值扫描（1 / 5 / 10 / 15 / 30）、软标签 vs 硬标签、代价矩阵不同比例
- [ ] **验收**：消融表能证明"非对称软标签"优于"整窗 max"与"尾部硬 max"

### B2. 真正的"预测"任务定义 ⭐ 推荐

- [ ] **现状问题**：现在标签只用当前及过去帧 → 这是 **detection 不是 prediction**，与仓库名不符
- [ ] **改标签**：$y_t = \mathbb{1}\!\left[\exists\,\text{impact} \in (t,\; t+H]\right]$，`H` 为预测时域
- [ ] 扫描 `H ∈ {0.25s, 0.5s, 1s, 2s}`，给出"提前量 ↔ 误报"的权衡
- [ ] **核心图**：横轴 Lead Time、纵轴 FAR 的 **Pareto 前沿曲线** ← 全文最有价值的一张图
- [ ] **验收**：能回答"提前 0.5s 预警时，每小时误报几次"

### B3. 校准决策替代手调状态机

- [ ] **现状问题**：`src/state_machine.py` 的 8 个阈值 + 连续次数全是手工调参，无语义、无保证
- [ ] **方案**：改用**保形预测（Conformal Prediction）**或 **Neyman-Pearson 决策**，
      给出"FPR ≤ α 下预警率最大"的可证明保证
- [ ] 对照实验：手调状态机 vs 校准决策（在相同 FPR 下比较检测率/提前量）
- [ ] **验收**：能给出一条带理论保证的决策规则，且其实测 FPR 满足目标

### B4. 跨域泛化（可作为加分实验）

- [ ] 迁移矩阵：`URFD(实验室) → CAUCAFall(居家) → clips(自采)`
- [ ] 可选方法：简单的领域对齐（BN-statistics 迁移、CORAL、对抗域适应）
- [ ] **验收**：跨域性能下降幅度可量化，并给出至少一种缓解手段的效果

## 7. 指标规范（论文汇报口径）

| 类别 | 指标 | 用途 |
|------|------|------|
| 阈值无关 | AUC-ROC、PR-AUC、EER | 主表，与文献可比 |
| 固定工作点 | P@R=0.95、R@FPR=0.01 | 公平对比不同方法 |
| 分类细节 | 每类 P/R/F1、macro-F1、混淆矩阵 | 诊断 |
| 部署 | **FAR（次/小时）**、端到端延迟、模型体量 | 实际价值 |
| 预警专有 | **Lead Time**、提前量 ↔ FAR 曲线 | **差异化卖点** |
| 统计 | mean ± std（5 seeds）、bootstrap CI、配对显著性 | 严谨性 |

❌ **不要出现在论文中**：`score = avgF12 - 0.5·fp_rate`（自定义、无法比较）

## 8. 目标投稿对象

> CCF 目录以官方最新版为准，下列分档为参考。

| 优先级 | 目标 | 说明 |
|--------|------|------|
| 推荐主投 | `ICPR` · `ICIP` · `ICMI` | CCF-C，对"应用 + 系统 + 完整实验"最友好 |
| 方法向 | `ACCV` · `BMVC` · `FG` | CCF-C，更看重方法新颖性，难度更高 |
| 国内 / 练手 | `PRCV`、国内会议、workshop、demo track | 建议至少先投一次练手，走完 rebuttal 流程 |
| 期刊路线 | `Pattern Recognition Letters` · `IET Computer Vision` · `Journal of Visual Communication and Image Representation` | CCF-C 期刊，对 novelty 宽容但要求实验更完整，周期长 |
| 领域对口（非 CCF） | `IEEE AVSS` | 视频监控领域高度对口，审稿人懂你的问题 |
| ⛔ 暂不触碰 | CVPR / ICCV / ECCV / ACM MM / AAAI 及任何 CCF-A/B | 数据规模与方法深度差 1~2 个量级 |

## 9. 决策点（Gate）

```
Phase 0 完成 → 看 LOSO 后的真实数字：

  ├─ Acc ≥ 0.80 → 重心放【Phase 2 方法创新】+【Phase 1 baseline 对比】
  │                目标：ICPR / ICIP / ICMI
  │
  ├─ Acc 0.65 ~ 0.80 → 【Phase 2 (B1+B2)】+【Phase 3 跨域】
  │                    用"提前预警"的 Pareto 前沿作为主要卖点
  │                    目标：ICMI / AVSS / 期刊
  │
  └─ Acc < 0.65 → 转【Phase 4 数据集 + benchmark】路线
                  把 4 阶段标注做成贡献，性能问题交给排行榜
                  目标：PRCV / 期刊 dataset 方向
```

> ⚠️ 关键提醒：**掉下来不是坏事**。现在的 0.8732 很可能是受试者泄漏带来的虚高。
> 拿到真实数字才能讲一个诚实、可复现、经得起审稿的故事。
