八、萤石开放平台调用证据

本章说明系统如何调用萤石开放平台（open.ys7.com）获取家用萤石摄像头实时视频流，并给出项目内可查证的调用证据链。


一、接入背景与目标

1.系统定位：基于市面普及的萤石家用摄像头（C6N），实现对居家老人摔倒动作的非接触式实时识别，不要求老人佩戴任何穿戴设备。
2.接入目的：萤石摄像头默认不提供裸 RTMP 拉流地址，需通过萤石开放平台注册开发者应用、绑定设备后，由平台接口签发有时效的预览地址（RTMP 流），再将此流作为系统推理管线的实时视频源。
3.调用主体：本项目算法端（demo_live / 后端推理线程）消费萤石开放平台下发的 RTMP 预览流，完成拉流→检测→姿态→摔倒识别→画面展示与告警。


二、萤石开放平台调用流程（标准步骤）

1.注册开发者账号并创建应用，获得一对密钥：appKey、appSecret（控制台 open.ys7.com/console）。
2.绑定设备：把萤石摄像头 C6N 的设备序列号（EZV 开头）与设备验证码添加到开发者账号名下。
3.获取访问令牌 accessToken：
   接口：POST https://open.ys7.com/api/lapp/token/get
   参数：appKey、appSecret
4.查询设备列表（确认设备在线）：
   接口：POST https://open.ys7.com/api/lapp/device/list
   参数：accessToken
5.获取预览地址（RTMP）：
   接口：POST https://open.ys7.com/api/lapp/live/address/get
   参数：accessToken、deviceSerial、channelNo、protocol=2（RTMP）、quality
   平台返回带签名与有效期的 RTMP 地址。
6.将平台返回的 RTMP 预览地址写入系统配置，由推理管线拉流消费（见下节调用证据）。


三、系统内已落地的调用证据（代码仓库可查证）

1.萤石预览 RTMP 地址已作为系统默认视频源写入配置。
   位置：CareWatch-Backend-main/app/config.py 第 22 行
   action_video 默认值（注释即标注"默认RTMP视频流(萤石云)"）：
   rtmp://rtmp17open.ys7.com:1935/v3/openlive/BH0157193_1_1?expire=1788255272&id=1012414692045373440&t=37e22720f4bcd4bf78d10b4895707baed70215f0d2f9cc46f8b2848b1ea1ef70&ev=101&supportH265=0
   地址解析（该格式仅由萤石开放平台「获取预览地址」接口签发）：
     rtmp17open.ys7.com:1935   萤石开放平台 RTMP 接入服务器与端口
     BH0157193_1_1             设备序列号 BH0157193 + 监控点 channelNo=1
     expire                    流地址有效期（Unix 时间戳）
     id / t                    平台签发的访问标识与签名（鉴权用）
     ev=101                    能力标识位
     supportH265=0             显式关闭 H.265（配合本项目 OpenCV+ffmpeg 解码链路）
   结论：该地址内含平台签名的 id/t/expire，无法手工构造，只能来自开放平台预览接口的返回，即为调用萤石开放平台的直接证据。

2.独立推理服务同样以萤石预览流为默认输入。
   位置：CareWatch-Backend-main/inference_server.py
   命令行参数 --video 默认值即上述萤石 RTMP 地址，用法注释给出完整启动命令（含 --checkpoint、--api 上报数据服务）。

3.实时推理链路对萤石流的消费与处理。
   位置：fall_detection/src/demo_live.py
   支持以 rtmp:// 开头的网络流作为输入（--video），对萤石流自动处理：
   流地址含 & 特殊字符时整条加引号；H.265 编码自动经 ffmpeg 转码为 H.264 后由 OpenCV 读取；断线自动重连。
   实测（见《实测数据与功能测试报告》）：萤石 RTMP 流接入后完成实时检测，前端可观看 /video 实时标注画面。

4.前端设备页展示萤石设备证据。
   位置：Website/src/views/DeviceManage.vue
   页面渲染"智能摄像头 · 主设备 / 客厅萤石 C6N"，并展示以 EZV 开头的萤石设备序列号（EZV 为萤石设备序列号标准前缀），证明接入对象为真实萤石设备。
   生产构建产物 dist/assets/ 中亦含相同设备展示内容，随前端一起发布。

5.项目定位文档明确以萤石摄像头为载体。
   位置：Website/挑战杯项目介绍.txt
   项目定位"基于萤石摄像头的居家老人多维度安全监护平台"，说明复用市面普及的萤石家用摄像头作为非接触式监护前端。

6.配置与部署说明已固化萤石流接入方式。
   位置：fall_detection/docs/部署与运行说明与系统设计.txt、实测数据与功能测试报告.txt
   实时推理章节给出 RTMP 网络流（萤石云）的启动命令、预期输出与 profile 分段耗时；功能测试记录 RTMP 流实时推理链路实测通过。

五、结论

1.系统确已调用萤石开放平台：所消费的 RTMP 预览流地址由开放平台接口签名签发（含 id/t/expire 鉴权参数），已在 config.py 与 inference_server.py 中固化为默认视频源。
2.链路已实际打通：萤石流接入实时推理管线，前端设备页展示真实萤石 C6N 设备，实时推理与接口功能测试通过。
3.项目内证据集中于代码与前端展示；平台侧的开发者应用、设备绑定与接口调用报文等截图建议按第四节补齐，即可构成从平台申请到系统消费的完整证据闭环。
