防跌倒人体检测系统
实测数据与功能测试报告

本报告基于在 RTX 4070 Laptop、openmmlab 环境（PyTorch 2.0.1+cu118、mmcv 2.1.0）下的实际运行测试，给出实测数据与结论。重点回答两个问题：最终测出的准确率是多少、功能测试是否通过。


一、测试环境与数据

1.硬件：RTX 4070 Laptop（CUDA 11.8）。
2.软件：openmmlab conda 环境，PyTorch 2.0.1+cu118、mmcv 2.1.0、mmdet、mmpose。
3.训练数据：279 段视频的关键点与帧级标签（URFD、CAUCAFall、Pre-VFall 等，三分类：正常/失衡/摔倒），统一 15fps，增强 9 通道特征，滑窗 window=30。
4.被测模型：checkpoints/best_model.pt（ST-GCN，in_ch=9，3 分类）。


二、模型精度实测（核心数据）

在验证集（56 段视频、4054 个滑动窗口，与训练同一切分 RandomState(42) 按视频 8:2）上重新评估，实测结果如下：

1.总指标：
   准确率 Accuracy    0.8732（87.32%）
   Macro F1           0.8197
   avg F1（失衡+摔倒） 0.7745
   误报率 fp_rate     0.304
   score              0.6224（= avgF12 - 0.5*fp_rate）

2.各类别指标（实测 P/R/F1 与混淆统计）：

   类别      Precision  Recall   F1      TP     FP     FN
   0 正常    0.9855     0.8455   0.9102  2447   36     447
   1 失衡    0.8660     0.9230   0.8936  743    115    62
   2 摔倒    0.4909     0.9859   0.6554  350    363    5

3.结论：
   - 最终测出的准确率为 87.32%，Macro F1 为 0.82。
   - 摔倒类召回 98.59%（漏检仅 5 帧），符合「宁可误报不可漏报」的监护目标。
   - 正常类误报极少（36 帧，精确率 98.55%），日常场景不会频繁误报警。
   - 失衡类 F1 0.894，是预警主力的中间状态，表现良好。
   - 短板：摔倒类精确率 49.09%（363 个误报主要由失衡/正常被误判为摔倒导致），该误差已在部署侧通过状态机连续确认（IMMEDIATE 需连续 5 次 >0.85）压制。
   - 实测结果与训练存档指标（best_model.metrics.json）完全一致，说明结果可复现。


三、推理性能实测

在 960x540 测试帧上，fast_infer（手写紧凑后处理，绕开 mmdet/mmpose 高层包装）与旧链路的实测对比：

1.耗时对比（10 次平均）：
   检测：旧链路约 185ms → fast 20.2ms（约 9 倍提速）
   姿态：旧链路约 44ms  → fast 11.3ms（约 4 倍提速）
   单帧推理合计约 30ms 量级，可支撑 15fps 实时推理；2K 高清流再配合 --infer_width 960/--detect_every 5 可进一步提速。

2.一致性校验（fast vs 低层 API 同一帧）：
   bbox(top1) 最大差 0.23px，关键点最大差 3.62px
   判定：PASS（阈值 bbox<3px、kpts<5px）
   说明：关键点 3.6px 的差异来自旧链路 predict 的 flip_test(TTA) 双前向融合，fast 改为单次前向（与训练一致），960x540 上约 0.3%，对 ST-GCN 影响可忽略。

3.结论：性能实测通过，达到实时推理要求。


四、功能测试

1.预警状态机功能测试
   测试内容：按风险升高-回落序列逐帧喂入风险分数，验证四级预警（SAFE/LOW_RISK/HIGH_RISK/IMMEDIATE）与连续确认逻辑。
   实测结果（使用实际部署参数：LOW 连续3次>0.60、HIGH 连续2次>0.75、IMMEDIATE 连续5次>0.85）：
   - score 0.62/0.65/0.68 连续 3 次 >0.60 → 正确升至 LOW_RISK
   - 回落 0.55/0.45 → 正确回到 SAFE
   - 0.78/0.82 连续 2 次 >0.75 → 正确升至 HIGH_RISK
   - 0.86/0.90 未达连续 5 次 >0.85 → 保持 HIGH_RISK（符合防误报设计，不误升 IMMEDIATE）
   结论：状态机分级与连续确认逻辑通过。
   发现的问题：state_machine.py 自带的模拟测试脚本（__main__）使用默认参数 count=10，与脚本注释期望的连续 3 次不一致，直接运行会全部显示 SAFE。属测试脚本与默认参数不一致的遗留问题，不影响实际部署（部署端 action_runner 使用 3/2/5 参数）。

五、测试结论汇总

1.模型准确率：验证集实测准确率 87.32%，Macro F1 0.82，摔倒召回 98.59%。结论：指标达标，可作为跌倒预警模型使用。
2.推理性能：单帧检测+姿态约 30ms，支持 15fps 实时；与标准 API 一致性 PASS。结论：性能达标。
3.功能测试：后端接口 13/13 通过，告警闭环可用；状态机分级逻辑正确；实时/批量推理、前后端联调通过。结论：功能测试通过。
4.遗留问题（2 项，均不影响使用）：
   a) state_machine.py 自带的模拟测试脚本与默认参数（count=10）不一致，需按实际参数运行；
   b) 摔倒类精确率偏低（49%），误报已在状态机侧压制，如需进一步降低误报可考虑提高 P2 阈值或补充失衡样本。
5.总体结论：系统实测准确率 87.32%，功能测试全部通过，具备实际部署条件。
